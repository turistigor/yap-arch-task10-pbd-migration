## Список данных и способы защиты

Механизм защиты сильно зависит от контекста работы с данными (хранение/передача, админ/врач и другие). В нижеприведенной таблице предлагаются разные способы для разных сценариев.

| **Тип данных** | **Текущий способ хранения** | **Категория приватности** | **Механизм защиты** |
|---|---|---|---|
| _Медицинские данные_ |
| Персональные данные пациентов   | Excel, JPG, PDF         | ПДн               | **При передаче**: TLS</br>**При хранении**: шифрование данных в БД и бэкапов</br>**При отображении**: маскировка для сотрудников ресепшен и кассиров</br>**Доступ**: только авторизованные сотрудники (ресепшен, врачи, бухгалтерия по необходимости)</br>**Для аналитики**: обезличивание |
| Дополнительные данные пациентов | Excel, JPG, PDF         | Специальные ПДн   | **При передаче**: TLS</br>**При хранении**: шифрование данных в БД и бэкапов</br>**При отображении**: маскировка для сотрудников ресепшен и кассиров</br>**Доступ**: только врачи и уполномоченные сотрудники</br>**Для аналитики**: обезличивание |
| Журналы приема пациентов        | Excel                   | ПДн               | **При передаче**: TLS</br>**При хранении**: шифрование данных в БД и бэкапов</br>**При отображении**: полный доступ только у ресепшен и врачей, для администраторов — маскировка ФИО</br>**Доступ**: ресепшен, врачи, администраторы (только для аудита)</br>**Для аналитики**: обезличивание |
| Медицинские карты пациентов     | Excel                   | Медицинская тайна | **При передаче**: TLS</br>**При хранении**: обязательное шифрование с использованием сертифицированных СКЗИ (класс КС1/КС2)</br>**При отображении**: только лечащий врач и пациент (через ЛК)</br>**Доступ**: только лечащий врач и пациент, строгий аудит всех обращений</br>**Для аналитики**: обезличивание |
| Результаты анализов             | Excel                   | Медицинская тайна | **При передаче**: TLS</br>**При хранении**: обязательное шифрование с использованием сертифицированных СКЗИ</br>**При отображении**: только лечащий врач и пациент (через ЛК)</br>**Доступ**: только лечащий врач и пациент, строгий аудит всех обращений</br>**Для аналитики**: обезличивание |
| _Финансовые данные_ |
| Платежные данные пациентов | Файлы «1С: Бухгалтерия» | Финансовые ПДн | **При передаче:** TLS (между ККМ, 1С и сервером)<br>**При хранении:** токенизация номера карты, шифрование данных в БД и бэкапов<br>**При отображении:** для кассиров — полный доступ, для бухгалтеров — суммы видны, номера карт — только последние 4 цифры, для других — недоступны<br>**Для аналитики:** агрегированные данные без привязки к картам<br>**Доступ:** кассиры, бухгалтерия |
| Финансовые данные сотрудников | Файлы «1С: Бухгалтерия» | Финансовые ПДн | **При передаче:** TLS<br>**При хранении:** шифрование данных в БД и бэкапов<br>**При отображении:** маскирование сумм и номеров документов для сотрудников без полного доступа, полные данные — только у бухгалтеров и hr<br>**Для аналитики:** агрегированные данные (средняя зарплата, общий ФОТ) без идентификации конкретных сотрудников<br>**Доступ:** бухгалтерия, кадровый отдел, руководитель (ограниченно) |
| Списки ТМЦ | Файлы «1С: Торговля и склад» | Внутренние | **При передаче:** TLS<br>**При хранении:** шифрование бэкапов<br>**При отображении:** полный доступ — склад, бухгалтерия, закупщики; для других отделов — ограниченный доступ<br>**Для аналитики:** обезличивание (скрытие закупочных цен для внешних отчётов)<br>**Доступ:** склад, бухгалтерия, отдел закупок |


## Тегирование

### Наборы тэгов

Составлены два набора тэгов для обеспечения гибкости при построении политик доступа и обработки.

**Теги по типу данных**

Определяют категорию приватности и правовой статус информации.

| Тег | Значение | Категория приватности | Пример данных |
|---|---|---|---|
| PII | Персональные данные (Personally Identifiable Information)| ПДн | ФИО, дата рождения, телефон, email, адрес прописки, место работы/учебы |
| PHI | Медицинская тайна (Protected Health Information) | Специальные ПДн / Медицинская тайна | Диагнозы, история болезни, результаты анализов, хронические заболевания |
| PCI | Платежные данные (Payment Card Industry) | Финансовые ПДн / Платёжные данные | Номер карты, сумма оплаты, способ оплаты, данные транзакций |
| HR | Кадровые и зарплатные данные | ПДн / Налоговая тайна | Паспортные данные сотрудников, ИНН, СНИЛС, зарплата, налоги |
| TMC | Данные о ТМЦ | Внутренние / Коммерческая тайна | Номенклатура, закупочные цены, остатки на складе |
| Journal | Журналы приёма | ПДн | Время, дата приёма, ФИО врача и пациента |
| Audit | Логи доступа и аудита | Служебная | IP-адреса, время запросов, действия пользователей |

**Теги по принадлежности данных**

Описывают функциональную принадлежность данных и контекст их использования.

| Тег |	Значение |
|---|---|
| Patient_Data    | Данные пациентов (все, что относится к пациенту) |
| Employee_Data   | Данные сотрудников |
| Financial_Data  | Финансовые данные (платежи, учёт денежных средств) |
| Medical_Record  | Медицинские записи (карты, анализы, журналы) |
| Warehouse_Data  | Складские данные (1С:Торговля и склад) |
| Backup          | Резервные копии |
| System_Data     | Системные данные (аналитика) |

## Выбор технической платформы для реализации PdB

| Платформа | Работа с Excel и файловой 1С | Готовые паттерны (PII/PHI/PCI) | Data Lineage | Тип развертывания (Важно для PHI) | Порог входа и внедрение | Стоимость (Лицензии + Эксплуатация) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Apache Atlas** | **Сложно.** Нужны кастомные скрипты или хуки для парсинга файловых систем. | **Нет.** Писать регулярные выражения для поиска данных вручную. | **Отлично.** Автоматический граф на основе хуков. При передаче данных тег наследуется по цепочке автоматически. | **On-Premise** (Внутри защищенного контура компании). | **Высокий.** Нужна штатная команда DevOps и Data-инженеров. | **Низкая (лицензия $0).** Высокие затраты на ФОТ специалистов. |
| **DataHub** | **Сложно.** Готовых коннекторов под файловую 1С нет, требуется ручной импорт. | **Нет.** Требуется ручная разметка или внешняя автоматизация. | **Хорошо.** Автоматический Lineage на уровне таблиц и колонок для СУБД. Наследование тегов настраивается через внутренние правила. | **On-Premise** / Cloud. | **Средний.** Проще Atlas, но интеграция с файлами требует программирования. | **Низкая (лицензия $0).** Требуются ИТ-ресурсы на поддержку. |
| **OpenMetadata** | **Сложно.** Требует кастомных скриптов для разбора Excel. | **Нет.** Ограниченные базовые шаблоны, регулярные выражения настраиваются вручную. | **Средне.** Ориентирован на структурированные БД и BI-системы. Наследование тегов работает через механизм распространения. | **On-Premise** / Cloud. | **Средний.** Хорошие API, но автоматического разбора связей для файлов нет. | **Низкая (лицензия $0).** Нужны ИТ-ресурсы на кастомизацию. |
| **BigID** | **Отлично.** Сканирует сетевые папки и файловые бэкапы. | **Отлично.** AI-модели под диагнозы, МКБ, карты и персональные данные. | **Отлично.** Специализированный Lineage для неструктурированных данных. Находит дубликаты и зависимости между изолированными файлами. | **On-Premise** / Private Cloud. | **Средний.** Сложный продукт для ИБ, но не требует написания кода. | **Очень высокая.** Дорогие Enterprise-лицензии и поддержка. |
| **Collibra** | **Средне.** Есть коннекторы к файловым хранилищам, но требуется ручная привязка к бизнес-терминам. | **Хорошо.** Шаблоны привязаны к бизнес-глоссарию и регуляторным политикам. | **Хорошо.** Строит сквозной граф от источника до отчетов, но логика движения локальных файлов требует ручного описания. | **On-Premise** / Cloud. | **Высокий.** Требует долгого проектирования методологии и обучения сотрудников. | **Очень высокая.** Дорогое Enterprise-решение, длительное внедрение. |
| **OneTrust** | **Средне.** Есть модуль DataDiscovery, но интеграция с локальной 1С ограничена. | **Хорошо.** Базовые шаблоны регуляторики и комплаенса. | **Средне.** Граф потоков данных строится в основном декларативно через опросники. Автоматического наследования тегов в файлах нет. | Преимущественно **Cloud** (SaaS), On-Premise доступен только в спец-пакетах. | **Высокий.** Перегруженный интерфейс, длительный процесс внедрения. | **Высокая.** Модульная оплата, дорогие ежегодные подписки. |
| **DataGrail** | **Неприменимо.** Работает только через API с облачными SaaS-сервисами. | **Средне.** Только стандартные облачные структуры PII. | **Нет.** Data Lineage отсутствует. Система видит только конечные точки хранения данных. | Только **Cloud** (SaaS). | **Низкий.** Быстрый запуск в облачной инфраструктуре за дни. | **Средняя.** Зависит от количества коннекторов, но файлы не закроет. |

При выборе были учтены следующие факторы:
1. Необходимость тегировать имеющиеся локальные файлы. 
2. Возможность on-premise использования для выполнения требования к локализации ПДн на територии РФ.
3. Поддержка DataLineage для реализации отслеживания.
4. Желательна минимизация затрат.
5. Желательна минимизация сложности развертывания и сопровождения.

**Решение**

Основные кандидаты: 
- **BigID**: функциональный, но дорогой;
- **DataHub**: бесплатный, но нуждающийся в кастомизации.
