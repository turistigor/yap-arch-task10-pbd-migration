# Задание 5. Разработка cutover-плана

## Описание стратегии

Для реализации выбрана комбинация стратегий Parallel Run и Branch by Abstraction. В плане миграции можно выделить 4 крупных этапа:
- MVP.
- Запуск сервисов внутреннего функционала (медицинские данные, кроме анализов) вместе с ручной обработкой.
- Запуск сервисов, связанных с интеграциями (оплата, анализы) вместе с 1С-системами.
- Доработки оставшихся требований.

Данный вариант позволяет избежать резких переключений, дробя отрезки одновременной работы двух систем по разным доменам. Это позволяет распределять сложность миграции между разными отделами по времени, чтобы минимизировать риски ошибок и отказов из-за перегрузок.

Основными преимуществами данного подхода являются:
- параллельность запуска с legacy-системой обеспечивает возможность отката;
- временные отрезки параллельной работы систем относительно небольшие;
- параллельная работа затрагивает не всю системы, а определенные домены, что упрощает управление.

Основные трудности:
- синхронизация данных при параллельной работе персонала в двух системах;
- дополнительные издержки во время параллельной работы (оборудование, энергия);
- повышенная нагрузка на сотрудников из-за дублирования данных в двух системах;
- согласованность версий функционала и API в legacy и новой системах.

## Минимизация рисков
Срыв сроков:
- невысокая гранулярность сервисов, для уменьшения сложности взаимодействий;
- найм разработчиков на ранних стадиях;
- автоматизация разработки на ранних стадиях;
- уменьшение времени онбординга за счет README.md, асинхронных коммуникаций,взаимообучения, автоматизации и четкой постановки задач.;
- наличие плана и регулярная синхронизация между командами при работе над кросс-функциональными фичами;
- обучение персонала для уменьшения сопротивления нововведениям.

Ошибки в требованиях:
- быстрый выпуск MVP для скорого фидбека от тестовых пользователей;
- выявление процессов: опросы и анкеты, интервью и фокус-группы, воркшопы и мозговые штурмы, наблюдение и слежка, анализ потоков данных и оргструктуры;
- создание источника истинности.

Баги:
- pазвертывание тестовой инфраструктуры на ранних стадиях;
- code coverage в CI с самого начала.

Критические проблемы в работающей/старой системе:
- уход от проблемных компонентов старой системы в первую очередь.

Потеря производительности ИТ-системы:
- реализация стратегии автомасштабирования на ранних стадиях;
- нагрузочное тестирование перед выпуском в production;
- мониторинг.

Потеря производительности всей организации:
- минимизация повышенной нагрузки на сотрудников;
- механизмы исправления ошибок.

Рассинхронизация систем
- автоматические сверки данных в системах за день;
- ограничение записи в новую систему при отсутствии данных в старой;
- версионирование интерфейсов;
- тестирование, в том числе регресс перед релизом.
